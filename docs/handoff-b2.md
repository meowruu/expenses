## 1. Overview & Architectural Guarantees

This document serves as the official contract and handoff for team members (**F1**, **B1**, **B3**, **B4**). The models and repository interfaces define the data layer boundary for the privacy-first UPI expense tracker.

### Strict Privacy & Storage Invariants
1. **Zero Raw SMS Storage (Privacy Rule):** Under no circumstance is raw SMS body text or unparsed message content stored, logged, or included in any entity. Only structured financial metadata is retained.
2. **Integer Arithmetic for Currency (`amountPaise: Long`):** Currency is represented strictly in paise (`1 INR = 100 paise`) using `Long`. `Float` and `Double` are strictly prohibited to prevent financial rounding errors.
3. **Deduplication:** The `TransactionRepository.insert` method checks the unique bank reference number (`refNumber`) and returns `false` if an entry with the same reference number already exists.
4. **Self-Transfer Exclusion:** User-owned UPI IDs are tracked via `MyUpiIdRepository` to exclude internal transfers from spending calculations.

/**

### 2.2 `Transaction`
```kotlin
package com.team.expensetracker.data.model

/**
 * Represents a parsed financial transaction.
 *
 * Privacy Rule Compliance:
 * Strictly stores only parsed, structured financial attributes.
 * Zero raw SMS text is stored.
 *
 * @property id Unique identifier for the transaction (autogenerated; 0L for unpersisted entities).
 * @property amountPaise Transaction amount in paise (1 INR = 100 paise). Long, never Float or Double.
 * @property type The transaction direction ([TransactionType.DEBIT] or [TransactionType.CREDIT]).
 * @property merchant The name of the merchant, payee, or counterparty (nullable).
 * @property upiId The UPI ID associated with the transaction (nullable, e.g. "merchant@bank").
 * @property refNumber Bank reference number / UTR for transaction deduplication (nullable).
 * @property date Epoch timestamp in milliseconds when the transaction occurred.
 * @property bank The issuing bank name or sender identifier (e.g., "HDFC", "SBI", "AXISBK").
 * @property category The assigned expense category (e.g., "Food", "Shopping", "Bills").
 */
data class Transaction(
    val id: Long = 0L,
    val amountPaise: Long,
    val type: TransactionType,
    val merchant: String?,
    val upiId: String?,
    val refNumber: String?,
    val date: Long,
    val bank: String,
    val category: String
)
```

## 3. Repository Interfaces (`com.team.expensetracker.data.repository`)

### 3.1 `TransactionRepository`
```kotlin
package com.team.expensetracker.data.repository

import com.team.expensetracker.data.model.Transaction
import kotlinx.coroutines.flow.Flow

interface TransactionRepository {

    /**
     * Inserts a transaction into persistent storage.
     *
     * Deduplication requirement:
     * If a transaction with the same reference number ([Transaction.refNumber]) already exists
     * in the repository (and is non-null/non-blank), insertion is rejected and returns `false`.
     * If the transaction is successfully inserted, returns `true`.
     *
     * @param tx The [Transaction] entity to insert.
     * @return `true` if inserted successfully; `false` if rejected due to duplicate refNumber.
     */
    suspend fun insert(tx: Transaction): Boolean

    /**
     * Observes all recorded transactions ordered by date descending.
     *
     * @return A [Flow] emitting the updated list of all [Transaction] records.
     */
    fun observeAll(): Flow<List<Transaction>>

    /**
     * Observes the total expenditure (in paise) within the specified date range.
     *
     * Excludes self-transfers (transfers to/from user's own UPI IDs) and non-debit entries.
     *
     * @param monthStart Start epoch timestamp in milliseconds (inclusive).
     * @param monthEnd End epoch timestamp in milliseconds (inclusive).
     * @return A [Flow] emitting the total spending in paise for the given period.
     */
    fun observeMonthTotal(monthStart: Long, monthEnd: Long): Flow<Long>

    /**
     * Observes the category-wise spending breakdown within the specified date range.
     *
     * @param monthStart Start epoch timestamp in milliseconds (inclusive).
     * @param monthEnd End epoch timestamp in milliseconds (inclusive).
     * @return A [Flow] emitting a map of category names to total spending in paise for the given period.
     */
    fun observeCategorySummary(monthStart: Long, monthEnd: Long): Flow<Map<String, Long>>

    /**
     * Updates the category of an existing transaction.
     *
     * @param id The unique identifier ([Transaction.id]) of the transaction to update.
     * @param category The new category name to assign.
     */
    suspend fun updateCategory(id: Long, category: String)

    /**
     * Deletes all transactions from persistent storage.
     *
     * Supports the privacy data-wipe feature ("delete all data").
     */
    suspend fun deleteAll()
}
```

### 3.2 `PayeeRuleRepository`
```kotlin
package com.team.expensetracker.data.repository

interface PayeeRuleRepository {

    /**
     * Retrieves the user-assigned category for the specified UPI ID.
     *
     * @param upiId The payee UPI identifier (e.g. "swiggy@icici").
     * @return The assigned category name if a rule exists for [upiId], or `null` if no rule is found.
     */
    suspend fun getCategoryFor(upiId: String): String?

    /**
     * Saves or updates a category rule for the specified UPI ID.
     *
     * If a rule for [upiId] already exists, its category will be updated to [category].
     *
     * @param upiId The payee UPI identifier (primary key).
     * @param category The category name to associate with this payee.
     */
    suspend fun saveRule(upiId: String, category: String)
}
```

### 3.3 `MyUpiIdRepository`

package com.team.expensetracker.data.repository

import com.team.expensetracker.data.model.MyUpiId
import kotlinx.coroutines.flow.Flow

interface MyUpiIdRepository {

    /**
     * Observes the complete list of user-owned UPI IDs.

     * @return A [Flow] emitting the updated list of [MyUpiId] records.

    fun observeAll(): Flow<List<MyUpiId>>

    /**
     * Adds a user-owned UPI ID to the repository.
     *
     * @param id The UPI ID string to add (e.g., "myname@okhdfcbank").

    /**
     * Removes a user-owned UPI ID from the repository.
     *
     * @param id The UPI ID string to remove.
     */
    suspend fun remove(id: String)

    /**
     * Checks whether the specified UPI ID belongs to the user.
     *
     * @param id The UPI ID string to verify.
     * @return `true` if the UPI ID is registered as user-owned; `false` otherwise.
     */

## 4. Integration Guide for Team Members

- **For F1 (Frontend):**
  - Start screen mockups and state binding using these interfaces.
  - `observeAll()` drives the recent transactions feed on the Home dashboard.
  - `observeMonthTotal(monthStart, monthEnd)` drives the monthly expenditure card.
  - `observeCategorySummary(monthStart, monthEnd)` drives the category chart and breakdown list.
  - `updateCategory(id, category)` binds to the Transaction Detail screen category editor.
  - `MyUpiIdRepository` binds to the "My UPI IDs" settings screen.

- **For B1 (Parser & Categorizer):**
  - Construct `Transaction` instances using `amountPaise = (amountInRupees * 100).toLong()`.
  - Pass the parsed model to `TransactionRepository.insert(tx)`. If `insert` returns `false`, the message was a duplicate and can be safely ignored.
  - Query `PayeeRuleRepository.getCategoryFor(upiId)` before applying fallback keyword heuristics.
  - When a user changes a category in UI, save the rule via `PayeeRuleRepository.saveRule(upiId, category)`.

- **For B4 (Security):**
  - Call `TransactionRepository.deleteAll()` to implement the backend for the "Delete all data" wipe button.
  - No raw SMS field exists in `Transaction`, satisfying the privacy compliance audit.
